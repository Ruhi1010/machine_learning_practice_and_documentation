Section 01Foundations

Why Do We Need Seaborn?

The problem

Matplotlib draws anything you ask it to — but it asks you to do all the statistics first. Say you want average temperature per city, with error bars showing the spread. In pure Matplotlib:

the_matplotlib_way.py
means = temps.mean(axis=1)
errors = temps.std(axis=1)
fig, ax = plt.subplots()
ax.bar(cities, means, yerr=errors, capsize=4)
ax.set_ylabel("Temperature (\u00b0C)")
ax.set_title("Average Temperature by City")

Now the same chart in Seaborn:

the_seaborn_way.py
sns.barplot(data=df, x="city", y="temp")

One line. Seaborn computed the mean per city, computed the uncertainty, drew the error bars, colored the categories, and labeled both axes from the column names — all from a tidy DataFrame.

  • Aggregation is automatic — you pass raw rows, Seaborn computes the summary.
  • Axis labels and legends come from your DataFrame's column names.
  • Splitting by a category is one keyword (hue=), not a loop.
  • Statistical chart types (KDE, violin, box, regression) are built in, not hand-rolled.
  • Defaults are designed to look reasonable without tuning.
Data Science Insight

Seaborn does not replace Matplotlib — it sits on top of it. Every Seaborn chart is a Matplotlib figure underneath, which is why you can still call plt.title(), ax.set_ylim(), or plt.savefig() on the result.

Where Seaborn sits

Seaborn reads a Pandas DataFrame and issues Matplotlib drawing calls on your behalf. Both layers stay available to you at all times.

Common Mistake

Assuming Seaborn replaces Matplotlib entirely, then getting stuck the first time you need something Seaborn doesn't expose — a custom y-limit, a specific figure size, a saved file. The answer is always the Matplotlib layer underneath, not a missing Seaborn feature.

Section 02Interactive reshape

Tidy Data — Long vs Wide

Why this section exists

Seaborn's whole API is built on one assumption: one row per observation, one column per variable. Get the shape right and every chart is a one-liner. Get it wrong and nothing works, for reasons the error message rarely explains.

The dataset, in wide form

This is how the temperature data has looked so far — cities down the side, days across the top. Natural to read, wrong shape for Seaborn.

Wide format: 5 rows × 7 columns. The day variable is spread across column names, not stored as data.

The same data, in long form

Melting it gives one row per reading — 35 rows, three columns. Every variable now lives in a column where Seaborn can address it by name.

notebook cell
# wide -> long
wide = pd.DataFrame(temps, index=cities, columns=days)
df = wide.reset_index().melt(
    id_vars="index",
    var_name="day",
    value_name="temp"
).rename(columns={"index": "city"})
print(df.shape)
print(df.head())
Output
(35, 3)

Which columns map to what

Once the data is long, every Seaborn call is just naming columns.

Seaborn parameterColumn from our dfWhat it controls
x="day"Horizontal position
y="temp"Vertical position
hue="city"Color — splits into one series per value
col= / row="city"Splits into separate subplots (figure-level only)
size= / style=any columnMarker size or line style per group
Pro Tip

If you're ever unsure whether your data is tidy, ask: "is one of my variables stored in the column headers instead of in a column?" If yes, it needs melting. In the wide table above, the day of the week is exactly that.

Common Mistake

Passing wide data and then trying to use hue="city". There is no column called city in wide form — the cities are the index — so Seaborn raises a key error. Melt first, then plot.

Section 03Live plotter

Relational Plots

lineplot — trends over an ordered variable

The payoff for tidying the data: one call draws every city, colors them, and builds the legend.

notebook cell
sns.lineplot(data=df, x="day", y="temp", hue="city", marker="o")
Output
(five colored lines, one per city, with an automatic legend)

Compare that to the Matplotlib version from the previous note, which needed an explicit loop, five manual label= arguments and a legend() call.

The hue parameter — interactive

Turn hue on and off. Without it, Seaborn treats all 35 rows as one group and aggregates them into a single line with a confidence band.


      

      

    


    

      Data Science Insight
      
When several rows share the same x value, lineplot doesn't draw them all — it plots the mean and shades a confidence interval around it. That shaded band is Seaborn doing inferential statistics for you, quietly, by default.

    


    
scatterplot — relationships without order

    
Same grammar, different geometry. Here each city becomes one point: average temperature against day-to-day volatility.

    

      
notebook cell

      
summary = df.groupby("city")["temp"].agg(["mean", "std"]).reset_index()
sns.scatterplot(data=summary, x="mean", y="std", hue="city", s=120)

    

    


    

      Common Mistake
      
Being surprised by the shaded band around a line and assuming it's a bug. It's the 95% confidence interval, computed by bootstrapping. If you want the raw lines with no interval, pass errorbar=None.

Distribution Plots


    
histplot — counts in bins

    
Same idea as Matplotlib's hist(), but it reads a column by name and can split by category.

    

      
notebook cell

      
sns.histplot(data=df, x="temp", bins=7, kde=True)

      
Output
(7 bars covering 2°C to 33°C, with a smooth density curve overlaid)

    


    
kdeplot — a smooth density estimate

    
A KDE replaces bars with a continuous curve. It makes no bin-boundary decisions, but it does make a smoothing decision instead — controlled by the bandwidth.

    

      
notebook cell

      
sns.kdeplot(data=df, x="temp", fill=True, bw_adjust=1)

    


    
Distribution explorer — interactive

    
All 35 readings. Switch representations and watch how the same numbers can look smooth or lumpy depending entirely on your settings.

    

      

        

          
        

        

        

      

      

      

    


    

      Data Science Insight
      
Lower bw_adjust makes the curve follow the data more closely, revealing detail — and noise. Higher values smooth it toward a single hump. Neither is "correct"; the curve is an estimate, and the bandwidth is your assumption about how much structure is real.

    


    
Why this distribution is bimodal

    
The curve has two clear humps because the dataset mixes a very cold city with several warm ones. That's a real feature of the data, not an artifact — and it's exactly the kind of thing a mean would hide.

    


    

      Common Mistake
      
Reading the y-axis of a KDE as a probability. It's a density — the area under the curve sums to 1, not the height. A peak of 0.04 doesn't mean "4% chance"; only an area between two x values has that meaning.

Categorical Plots


    
The family

    
Categorical plots put a category on one axis and a numeric variable on the other. They differ only in how much of the distribution they show.

    

      
FunctionShowsBest when

      
sns.barplot()A single summary (mean) per category, plus error barsYou want the headline number

      
sns.boxplot()Median, quartiles, whiskers, outliersYou want the spread, compactly

      
sns.violinplot()Full density shape per categoryThe shape itself matters (bimodal? skewed?)

      
sns.stripplot()Every individual observation as a dotFew data points — show them all

      
sns.countplot()How many rows per categoryCounting, not measuring

sns.barplot(data=df, x="city", y="temp")

      Real-World Use Case
      
A bar chart of group means is the most common chart in published research and the most criticized — two groups with identical means can have completely different spreads. Overlaying a stripplot on a boxplot shows both the summary and the raw points, which is why that combination is standard practice.

    


    

      Common Mistake
      
Using a violinplot on very few observations per group. With seven readings per city, the "density curve" is mostly the KDE's smoothing assumption rather than real structure in the data. Boxplot or stripplot is the more honest choice at this sample size.

Themes & Palettes


    
set_theme — one call, global effect

    
sns.set_theme() takes three separable arguments: a style (background and grid), a context (element scaling), and a palette (colors).

    

      
notebook cell

      
sns.set_theme(style="whitegrid", context="notebook", palette="deep")

    

    

      
ArgumentOptionsControls

      
style=darkgrid, whitegrid, dark, white, ticksBackground color and gridlines

      
context=paper, notebook, talk, posterSize of labels, lines and markers

      
palette=deep, muted, pastel, viridis, coolwarm…The color sequence used for groups

    


    

      Pro Tip
      
context="talk" or "poster" scales up every text element at once — far easier than hand-tuning a dozen fontsize arguments when a chart is going on a slide.

    


    
Three kinds of palette

    
Choosing a palette isn't decoration — the wrong type actively misleads.

    

      

        
Qualitative — for unordered categories

        

        
Distinct hues, no implied ranking. Correct for our five cities, which have no natural order.

      

      

        
Sequential — for low-to-high values

        

        
One hue, increasing intensity. Correct for a temperature heatmap.

      

      

        
Diverging — for deviation from a midpoint

        

        
Two hues meeting at a neutral center. Correct for "above vs below average."

      

    


    
Theme builder — interactive

    
Every control maps directly to an argument in the set_theme() call above.

    

      

        

          
        

        

          
        

        

          
        

      

      

      

    


    

      Common Mistake
      
Using a rainbow or diverging palette for unordered categories. Color that varies in brightness implies magnitude, so readers infer a ranking among your cities that doesn't exist. Qualitative palettes keep brightness roughly constant precisely to avoid this.

Heatmaps & Figure-Level Grids


    
heatmap — the one function that wants wide data

    
Every other Seaborn function takes long form. heatmap() is the exception: it expects a rectangular matrix, exactly the wide table from Section 2.

    

      
notebook cell

      
matrix = df.pivot(index="city", columns="day", values="temp")
sns.heatmap(matrix, annot=True, fmt="d", cmap="YlOrRd")

      
Output
(a 5x7 grid of colored cells, each labeled with its temperature)

    

    
pivot() is the inverse of the melt() from Section 2 — long back to wide.

Axes-level vs figure-level

    
This is Seaborn's second big structural idea. Axes-level functions draw onto one Matplotlib Axes you already have. Figure-level functions create and manage the entire figure themselves — which is what lets them split data into a grid of subplots.

    

      
LevelFunctionsReturnsSupports col= / row=

      
Axes-levellineplot, scatterplot, histplot, boxplot, heatmapA Matplotlib AxesNo

      
Figure-levelrelplot, displot, catplot, pairplot, lmplotA FacetGrid objectYes

    

    

      
notebook cell

      
# figure-level: one small chart per city, automatically
sns.relplot(data=df, x="day", y="temp",
            col="city", kind="line",
            col_wrap=3, height=2.5, marker="o")

      
Output
(a 2x3 FacetGrid — five line charts, one per city, sharing axis ranges)

    

    

    
Compare this to the Matplotlib note's subplot loop: the grid layout, the shared y-axis range, the per-panel titles and the wrapping are all handled by col= and col_wrap=.


    

      Data Science Insight
      
Sharing axis limits across facets is the default and it matters. If each panel auto-scaled independently, Oslo's 2–6°C week would look identical in shape to Cairo's 28–33°C week. Shared scales preserve the comparison.

    


    

      Common Mistake
      
Calling plt.title() after a figure-level function and wondering why it lands on the last panel. Figure-level functions return a FacetGrid, not an Axes — use g.figure.suptitle() or g.set_titles() instead.

The Full Workflow, Start to Finish

    
Same dataset, one continuous script — reshape once, then let Seaborn do the statistics for every panel.


    

      
full_workflow.py

      
import numpy as np
import pandas as pd
import seaborn as sns
import matplotlib.pyplot as plt

sns.set_theme(style="whitegrid", context="notebook")

# 1. The data (from the NumPy note)
cities = ["Tokyo", "Cairo", "Oslo", "Lima", "Nairobi"]
days = ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]
temps = np.array([
    [18, 19, 21, 20, 22, 23, 21],
    [29, 31, 30, 33, 32, 30, 28],
    [4,  3,  5,  2,  6,  4,  3],
    [17, 18, 16, 19, 18, 17, 19],
    [24, 23, 25, 24, 26, 25, 24],
])

# 2. Reshape to tidy/long — the step everything else depends on
wide = pd.DataFrame(temps, index=cities, columns=days)
df = (wide.reset_index()
        .melt(id_vars="index", var_name="day", value_name="temp")
        .rename(columns={"index": "city"}))

# 3. Build a 2x2 figure
fig, axes = plt.subplots(2, 2, figsize=(13, 9))

# 4. Top-left: every city's week (relational, hue does the splitting)
sns.lineplot(data=df, x="day", y="temp", hue="city",
             marker="o", ax=axes[0, 0])
axes[0, 0].set_title("Weekly Temperatures")

# 5. Top-right: spread per city (categorical — boxplot keeps the quartiles)
sns.boxplot(data=df, x="city", y="temp", ax=axes[0, 1])
sns.stripplot(data=df, x="city", y="temp", color="black",
              size=4, alpha=0.6, ax=axes[0, 1])
axes[0, 1].set_title("Spread by City")

# 6. Bottom-left: distribution of all 35 readings
sns.histplot(data=df, x="temp", bins=7, kde=True, ax=axes[1, 0])
axes[1, 0].set_title("Distribution of All Readings")

# 7. Bottom-right: heatmap — pivot back to wide first
matrix = df.pivot(index="city", columns="day", values="temp")
sns.heatmap(matrix, annot=True, fmt="d", cmap="YlOrRd",
            cbar=False, ax=axes[1, 1])
axes[1, 1].set_title("City \u00d7 Day Heatmap")

# 8. Finalize through the Matplotlib layer
fig.tight_layout()
fig.savefig("seaborn_report.png", dpi=300, bbox_inches="tight")
plt.show()
