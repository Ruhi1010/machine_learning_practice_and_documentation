Section 01Foundations

Why Do We Need Matplotlib?

The problem

By now Tokyo's week lives in a NumPy array. Here it is, printed the only way arrays know how to present themselves:

notebook cell
print(tokyo_week)
Output
[18 19 21 20 22 23 21]

Technically correct. Completely unreadable at a glance — is it trending up? Is Thursday an outlier? A human eye answers that instantly from a picture and never from a row of digits.

  • Trends over time are invisible in a list of numbers, obvious in a line.
  • Comparing categories (five cities) means mentally re-scanning columns, every time.
  • Outliers and spread don't jump out of text — they jump out of a shape.
  • Nobody you explain results to wants to read an array. They want a chart.

The exact same array, plotted:

Data Science Insight

Matplotlib is the foundation plotting library for Python — nearly every other plotting tool (Pandas' .plot(), Seaborn) is either built on it or designed to interoperate with it.

plt is the universal convention, exactly like np and pd before it.

Common Mistake

Forgetting plt.show() in a plain .py script — the figure is built in memory but never actually displayed. Notebooks are more forgiving and often show the last figure automatically, which hides this habit until it breaks elsewhere.

Section 02Interactive anatomy

Anatomy of a Plot

Figure vs Axes

Two objects run every Matplotlib chart. A Figure is the whole canvas — the window or the saved image file. An Axes is one actual plot living inside it — its own x-axis, y-axis, title, and data. One Figure can hold many Axes.

notebook cell
fig, ax = plt.subplots(figsize=(6, 4))
ax.plot(days, tokyo_week)
ax.set_title("Tokyo — 7 Day Forecast")
ax.set_xlabel("Day")
ax.set_ylabel("Temperature (\u00b0C)")
plt.show()
Output
(displays the figure — one Axes, one line, a title and two axis labels)
Pro Tip

fig, ax = plt.subplots() is the recommended starting line for almost every plot, even a single one — it gives you an explicit ax to call methods on, instead of relying on Matplotlib's implicit "current axes."

Click each part — interactive

Every one of these is a real, individually addressable object.

Common Mistake

Mixing plt.title() (the pyplot shortcut) with ax.set_title() (the object-oriented call) inconsistently across a script with multiple subplots. Once you have more than one Axes, plt.title() only ever affects whichever one is "current" — often not the one you meant.

Section 03Live plotter

Line & Scatter Plots

Line plots — for trends

ax.plot() connects points in order — the right choice whenever order matters, like a week of days.

notebook cell
fig, ax = plt.subplots()
ax.plot(days, temps[1], marker="o")   # Cairo's week
plt.show()
Output
(a rising-and-falling line, one marker per day, for Cairo)
Scatter plots — for relationships

ax.scatter() places unconnected points — the right choice when you're asking whether two variables relate, not tracking an order.

notebook cell
city_avg = temps.mean(axis=1)
city_std = temps.std(axis=1)
fig, ax = plt.subplots()
ax.scatter(city_avg, city_std)   # average vs. day-to-day swing
plt.show()
Output
(5 unconnected points — one per city, average temp vs. volatility)

Looking for clusters or correlation?Scatter plot

    


    

      Common Mistake
      
Using a line plot to connect points that have no real order — like connecting five unrelated cities in whatever order they happen to sit in an array. The connecting line implies a relationship between neighbors that doesn't exist. A scatter plot has no such implication.

Bar Charts & Histograms


    
Bar charts — comparing categories

    
ax.bar() compares a value across distinct categories — here, average temperature per city.

    

      
notebook cell

      
fig, ax = plt.subplots()
ax.bar(cities, temps.mean(axis=1))
ax.set_ylabel("Average Temp (\u00b0C)")
plt.show()

      
Output
(5 bars, Cairo tallest, Oslo shortest)

    

    

      
    


    
Histograms — showing a distribution

    
A histogram is not a bar chart of categories — it bins a single continuous variable and counts how many values fall in each bin. Here, every one of the 35 temperature readings, regardless of city or day.

    

      
notebook cell

      
fig, ax = plt.subplots()
ax.hist(temps.flatten(), bins=7)
ax.set_xlabel("Temperature (\u00b0C)")
ax.set_ylabel("Count")
plt.show()

      
Output
(a lumpy distribution — two visible clusters, since Oslo and Cairo sit far apart)

    


    
Histogram bin explorer — interactive

    
All 35 readings, rebinned live. Fewer bins smooth things out; more bins reveal — or fabricate — structure.

Answers"How does A compare to B?""What does the spread of this variable look like?"

    


    

      Common Mistake
      
Treating a bar chart and a histogram as interchangeable. Feeding five city averages into ax.hist() — or 35 individual readings into ax.bar() — produces something technically renders but answers the wrong question.

Section 05Live grid

    
Subplots


    
One figure, many axes

    
plt.subplots(rows, cols) returns a grid of Axes at once — ax becomes a 2-D array you index into, one cell per chart.

    

      
notebook cell

      
fig, axes = plt.subplots(2, 3, figsize=(10, 6))
for i, city in enumerate(cities):
    row, col = i // 3, i % 3
    axes[row, col].plot(days, temps[i])
    axes[row, col].set_title(city)
fig.tight_layout()
plt.show()

      
Output
(2x3 grid — 5 small line charts, one empty cell)

    


    
Grid builder — interactive

    
Choose a grid size and watch each city fill in, one Axes at a time, left to right, top to bottom.

    

      

        

        

      

      

      

        
      

    


    

      Pro Tip
      
fig.tight_layout() automatically adjusts spacing so titles and labels in a grid don't overlap each other — cheap to add, and almost always worth adding.

    


    

      Common Mistake
      
With plt.subplots(1, n), axes comes back as a plain 1-D array, not 2-D — so axes[0, 1] raises an error where axes[1] was needed. The indexing shape depends on how many rows and columns you asked for.

Annotating a specific point

    
ax.annotate() labels one exact point — useful for calling out a maximum, minimum, or anomaly instead of leaving the reader to hunt for it.

    

      
notebook cell

      
peak_day = temps[1].argmax()
ax.annotate(f"Peak: {temps[1][peak_day]}\u00b0C",
            xy=(peak_day, temps[1][peak_day]),
            xytext=(peak_day, temps[1][peak_day] + 3),
            arrowprops=dict(arrowstyle="->"))

      
Output
(an arrow pointing at Cairo's hottest day, labeled "Peak: 33°C")

Section 07Live comparison

    
Multi-Series Plots & Saving


    
Every city, one chart

    
Calling ax.plot() multiple times on the same Axes overlays every line together — a legend is what keeps them distinguishable.

    

      
notebook cell

      
fig, ax = plt.subplots(figsize=(8, 5))
for i, city in enumerate(cities):
    ax.plot(days, temps[i], marker="o", label=city)
ax.set_title("Weekly Temperatures — All Cities")
ax.legend()
plt.show()

    


    
Toggle cities on the comparison chart — interactive

    

      

      

        
      

    


    
Saving a figure

    
A figure isn't just for the screen — savefig() exports it as a file, ready to drop into a report or a slide deck.

    

      
notebook cell

      
fig.savefig("weekly_temperatures.png", dpi=300, bbox_inches="tight")

    

    

      
ParameterWhat it controls

      
dpiResolution — higher for print, lower is fine for screens

      
bbox_inches="tight"Trims extra whitespace around the figure

      
File extensionFormat — .png, .pdf, .svg all work from the same call

    


    

      Common Mistake
      
Calling plt.show() before fig.savefig(). In some environments, showing a figure clears it from memory — the saved file comes out blank. Save first, or save and show as two independent calls.

Case StudyEnd to end

    
The Full Workflow, Start to Finish

    
Same dataset, one continuous script — every step is something you already built in this note, chained together into the figure you'd actually hand someone.


    

      
full_workflow.py

      
import numpy as np
import matplotlib.pyplot as plt

# 1. The data (from the NumPy note)
cities = ["Tokyo", "Cairo", "Oslo", "Lima", "Nairobi"]
days = ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]
temps = np.array([
    [18, 19, 21, 20, 22, 23, 21],
    [29, 31, 30, 33, 32, 30, 28],
    [4,  3,  5,  2,  6,  4,  3],
    [17, 18, 16, 19, 18, 17, 19],
    [24, 23, 25, 24, 26, 25, 24],
])

# 2. Build a 2x2 figure: trend, comparison, distribution, relationship
fig, axes = plt.subplots(2, 2, figsize=(12, 8))

# 3. Top-left: every city's week overlaid (multi-series line)
for i, city in enumerate(cities):
    axes[0, 0].plot(days, temps[i], marker="o", label=city)
axes[0, 0].set_title("Weekly Temperatures")
axes[0, 0].set_ylabel("\u00b0C")
axes[0, 0].legend(fontsize=8)

# 4. Top-right: average per city (bar)
city_avg = temps.mean(axis=1)
axes[0, 1].bar(cities, city_avg, color="#22d3ee")
axes[0, 1].set_title("Average Temperature by City")

# 5. Bottom-left: spread of all 35 readings (histogram)
axes[1, 0].hist(temps.flatten(), bins=7, color="#a78bfa")
axes[1, 0].set_title("Distribution of All Readings")
axes[1, 0].set_xlabel("\u00b0C")

# 6. Bottom-right: average vs volatility (scatter)
city_std = temps.std(axis=1)
axes[1, 1].scatter(city_avg, city_std, s=80)
for i, city in enumerate(cities):
    axes[1, 1].annotate(city, (city_avg[i], city_std[i]))
axes[1, 1].set_title("Average vs Day-to-Day Swing")

# 7. Clean up spacing and export
fig.tight_layout()
fig.savefig("weekly_report.png", dpi=300, bbox_inches="tight")
plt.show()
